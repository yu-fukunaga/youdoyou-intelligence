# スペック作成

## 目的

タスクの目的・背景と具体的な手順を記録した仕様書を `spec/` に生成する。

---

## ファイル命名規則

```
spec/NNNN-{kebab-case-name}.md
```

- `NNNN`: 4桁ゼロ埋めの連番。`spec/`直下(`spec/done/`含む)の既存ファイルの最大番号+1を使う
- `{kebab-case-name}`: 機能・タスク名をケバブケースで

---

## 作成手順

1. `ls spec/*.md spec/done/*.md` などで既存ファイルの連番を確認し、次の番号(4桁ゼロ埋め)を決める
2. `date -u +"%Y-%m-%dT%H:%M:%S.000Z"` で現在時刻(ISO8601)を取得する
3. ユーザーの指示とコードの文脈から、下記フォーマットに従って front matter + spec 本文を生成する
4. 不明な点はコードを読んで把握する。それでも不明なら確認する

---

## フォーマット

front matter は必須。すべてのspecファイルの先頭に付与する。

````markdown
---
id: "0013"
status: "backlog"
created: "2026-07-07T12:37:57.634Z"
modified: "2026-07-07T12:37:57.634Z"
completedAt: null
labels: ["client"]
order: ""
---

# {機能名}

## 目的・背景

（なぜこれを作るか。どんな問題を解くか。1〜3文）

---

## Details

### Task 1: {タスク名}

（何をするか。どのファイル・関数・APIを変えるか。具体的に）

### Task 2: {タスク名}

（同上）

...（タスクの数に上限はない。必要な数だけ追加する）
````

front matter の各フィールド:

- `id`: ファイル名の連番部分(`NNNN`)のみ（例: `0013`）。ファイル名をリネームしてもidを書き直さずに済むようにするため
- `status`: 新規作成時は常に `"backlog"`
- `created` / `modified`: 手順2で取得したISO8601タイムスタンプを同じ値で設定
- `completedAt`: 新規作成時は常に `null`
- `labels`: 変更が及ぶ領域を、リポジトリのルート直下ディレクトリ名(隠しディレクトリ含む)で指定する。複数選択可。それ以外の値は使わない
  - `ls -d */ .*/ ` 等でその時点のルート直下ディレクトリを確認し、そこから選ぶ(例: `client`, `server`, `.github` など。ディレクトリが増減すれば選択肢も追従する)
- `order`: 新規作成時は常に `""`

---

## 注意事項

- 「なぜ作るか」を中心に書く。実装詳細は書かない
- タスクは具体的な作業単位に分解する
